# Session 098 — Pre-1.0 audit

**Date:** 2026-05-25
**Outcome:** Wrote `V0X-AUDIT.md` — a comprehensive
retrospective covering the v0.x state across every
feature category, every documented deferral, and the
pre-1.0 priority list. Docs-only session; no code
changes.

## The decisive observation

97 sessions of incremental feature work have produced
a coherent language. The next round of work splits
into two distinct piles: (1) closing gaps that affect
common workloads (const-eval overflow, chained binop
hints, `.sum` generalization), and (2) self-hosted
bootstrap. Before either, it's useful to have a
single document that captures the full state — what's
shipped, what's deferred-and-why, and what 1.0 needs.

Each deferral now has a clear rationale recorded. The
deferral list is the v0.x equivalent of "known issues"
— but every entry has either a workaround (parens,
suffixes, struct wrappers) or a clear future session
that addresses it.

The audit also surfaced patterns that emerged
naturally across the sessions:

- **The "decisive observation" framing** in every
  session doc — "feature X reduces to threading data
  Y through site Z." Often the data was already
  there; the session just connected it.
- **Two-layer fixes**: a feature lands in the checker
  for type-time errors, then the same shape gets
  echoed in codegen / lower for runtime errors.
  Sessions 071 (trait defaults) → 087 (primitive
  impls) → 093/097 (diagnostic polish) all share this.
- **Matrix-based pattern algorithms** for tuple
  exhaustiveness (session 089) and unreachability
  (session 094) reuse the same `specialize_*` free
  functions — adding one concept (per-arm usefulness)
  cost just one new function next to the existing
  ones.

## What the audit captures

The audit doc has these sections:

1. **Mission recap** — the original constraints (no
   GC, native via Cranelift, Rust-flavored syntax).
2. **What works** — feature-by-feature breakdown:
   syntax, types, generics+traits, closures, iterators,
   memory model, modules, pattern matching, error
   handling, type inference, compilation pipeline,
   diagnostics.
3. **What's deferred** — every documented limitation,
   grouped by area (type inference, generics,
   numerics, iterators, memory model, diagnostics,
   other).
4. **Pre-1.0 priorities** — ordered list of what
   needs to land before "1.0".
5. **Self-hosted bootstrap** — the long-term goal,
   with prerequisites and rough effort estimate.
6. **Decisions that have held** — load-bearing
   choices from early sessions that haven't needed
   revisiting (i64 default, Cranelift backend, ARC,
   prelude in Rune, monomorphization).
7. **Where it's not** — explicit non-goals.
8. **What 1.0 looks like** — quality / completeness
   / self-hosted, not new features.

## Apparent bugs that aren't / explicitly deferred

The audit doc itself is meant to be a snapshot; it
will go stale as new sessions ship. Future sessions
should append to the relevant section if they unblock
a deferral, or note the new gap in the deferred list.

There's intentional overlap with LANGUAGE.md's
decision log — LANGUAGE.md is chronological-by-row;
V0X-AUDIT.md is categorical-by-feature. Different
slicing of the same underlying data.

## What's next

- **Const-eval overflow checks** — top of the
  pre-1.0 priority list. Reject `100u8 + 200u8` and
  `1000u8` at compile time.
- **Chained binop hint propagation** — `1 + 2 + a:
  i32` works without parens.
- **Floating-point Vec elements** — unblock numeric
  workloads on f64.
- **Self-hosted bootstrap** — long-term.
